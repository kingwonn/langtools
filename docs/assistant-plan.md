## 1. 定位

ReadSphere 目前是「内容进来 → 分析沉淀 → 你去读」的**拉模式**。分身助手补上**推模式和对话模式**:

```
        ┌────────────────── ReadSphere 生态 ──────────────────┐
        │                                                      │
  RSS──▶ 流水线(已有) ──▶ 网站(已有) ──▶ Wiki+记忆库(已有)   │
        │                        │                             │
        │                        ▼                             │
        │        ┌─────── 分身助手(本方案)───────┐            │
  你 ◀──┼──推送──┤  · 每日摘要(已有)+事件情报     │            │
  你 ◀──┼──对话──┤  · 英语教练 / AI·投资问答      │◀── 读取 Wiki 记忆库
        │        │  · 个人学习档案(新)            │            │
        │        └────────────────────────────────┘            │
        └──────────────────────────────────────────────────────┘
```

核心原则:**助手不是孤立的聊天机器人,它读你的知识库、写你的学习档案**——网站沉淀领域记忆,助手沉淀个人记忆,两者互相喂养。

## 2. 架构(为扩展而设计)

```
┌─ 通道适配层 ─────────────────────────────────────────┐
│ FeishuAdapter(一期) WeChatAdapter(二期) …Telegram等  │   每个 adapter 只做两件事:
│        统一消息模型 {user, text, channel, msg_id}     │   收→标准化 / 标准回复→渠道格式
└───────────────────────┬──────────────────────────────┘
                        ▼
┌─ Agent 核心 (Cloudflare Worker) ─────────────────────┐
│ 意图路由(轻量,规则+LLM兜底):                          │
│   /coach 或检测到英文长句 → 英语教练                   │
│   /ask 或问句 → 领域问答                               │
│   /vocab /review → 学习档案查询                        │
│ 场景处理器(可插拔,新场景=新处理器):                    │
│   CoachHandler │ QAHandler │ DigestHandler │ …         │
└──────┬──────────────────┬────────────────────────────┘
       ▼                  ▼
┌─ 记忆层 ────────┐  ┌─ 知识层(只读,已有)─────────────┐
│ Workers KV:      │  │ 网站 wiki.json / analysis.json  │
│ · 个人档案       │  │ (经 GitHub raw 拉取,边缘缓存)  │
│ · 错题本/生词本  │  └─────────────────────────────────┘
│ · 近期对话窗口   │
└─────────────────┘
       ▼
┌─ LLM 层(复用已有 scripts/lib/llm.mjs 抽象)──────────┐
│ Anthropic 原生 / OpenRouter,模型可配置                │
└──────────────────────────────────────────────────────┘
```

**扩展点设计**(这版架构对以下未来需求零重构):

- **新渠道**:实现一个 adapter 即可(微信公众号、Telegram、邮件、网站内嵌聊天)
- **新场景**:实现一个 handler 即可(如「帮我把这段中文写成地道英文」「本周组合复盘」)
- **记忆升级**:KV 里的个人档案与网站 Wiki 记忆库同构(observation → 沉淀 → 巩固),未来可合并成统一记忆服务;错题本可导出 Anki
- **多模态**:飞书语音消息→语音转文字→现有文本链路;图片(如财报截图)→多模态模型,只改 handler 不动骨架
- **事件情报**:流水线检测到高分 insight(如重磅发布)→ 调用 Worker 的推送接口,复用摘要通道

## 3. 一期场景细节

### 3.1 英语教练 (CoachHandler)
- 你发任意英文 → 回复结构:✅ 改正后的句子 → 🔍 逐处错误解释(为什么错,中文) → 💬 更地道的说法(1-2 种,标注正式/口语) → 📌 本次要点存入错题本
- 高频错误自动归类(时态/介词/搭配/中式直译…),`/review` 生成周复盘
- 你发中文 + `/en` → 教你怎么用英文表达这句话(反向教练)

### 3.2 领域问答 (QAHandler)
- 英文回答 + 关键术语中文注解(和网站难度体系一致)
- **RAG on 自有知识**:先查你网站的 Wiki 词条与记忆时间线,命中则带着"你知识库里的上下文"回答并附词条链接;未命中走通用回答并提示"该概念尚未入库"
- 投资类问答自动附风险提示,不给具体买卖建议

### 3.3 个人学习档案 (KV 数据模型)
```
profile:   { level_estimate, interests[], goals, updated_at }
mistakes:  [ { error, correction, category, count, last_seen } ]   ← 错题本
vocab:     [ { word, meaning, source_msg, review_due } ]           ← 生词本(间隔复习)
sessions:  最近 N 轮对话摘要(控制上下文成本)
```

## 5. 成本与风险

- **资金**:Workers/KV 免费额度内;LLM 按对话量计,教练场景单条约 1-3k token,重度日用 50 条 ≈ 每月几美元(Sonnet 级)
- **风险**:飞书事件回调需要公网 URL(Workers 天然解决);Anthropic API 从 CF 边缘访问无障碍;个人档案存 KV 属敏感数据,只存学习相关内容,不存对话原文全量
- **安全**:Key 全部存 Workers secrets;飞书回调验签;仓库中不出现任何密钥
